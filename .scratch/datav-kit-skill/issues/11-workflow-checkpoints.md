# 工作流检查点与产物

Status: resolved
Type: grilling
Blocked by: 08

## Question

把原型优先工作流钉成可执行步骤：

1. 每一步的输入、输出、退出条件（① brief 澄清 → ② 出原型 → ③ 选定 → ④ 实现 → ⑤ 自检 → ⑥ 评审）。
2. 每步 agent 必须做 / 禁止做什么（尤其"未选定原型前不得进入实现"这类硬闸门）。
3. brief 澄清问什么（业务域、指标、数据源、交互、分辨率、主题……）——给一份最小问题清单。
4. 出原型时出几个、怎么呈现给用户选、用户如何反馈——**原型从 08 的四套模板（T1 三栏运维 / T2 两栏分析 / T3 单栏叙事 / T4 KPI 主导）里选 2–3 套改写**。
5. 自检清单怎么从设计规范派生、什么时候跑。
6. 评审之后怎么回写成 skill 修订项。
7. **回原型的触发条件**（06 已定）必须写进流程的硬闸门：改骨架或碰红线 → 回原型重选，不得就地改。
8. 自检清单要能查出"**硬编码值而非引用令牌**"（05 的令牌只有被用起来才有意义）。


## Answer

### 1. 六步：产物与退出条件

产物落在项目的 `design/` 目录，过程可追溯、评审有据可依。

| 步 | 产物 | 退出条件 |
| --- | --- | --- |
| ① 澄清 | `design/brief.md` | 7 项问题清单全部有答案 |
| ② 原型 | `design/prototype-*.html`（**2–3 个**） | 每个都能双击打开、控制台无报错 |
| ③ 选定 | `design/decision.md` | 用户明确选定一个 + 偏离登记（如有） |
| ④ 实现 | 项目代码 | 大屏在目标分辨率下可运行 |
| ⑤ 自检 | `design/self-check.md` | **全部红线项通过** |
| ⑥ 评审 | `design/review.md` | 评审记录 + skill 修订项已列出 |

### 2. 五条硬闸门

1. **未选定原型前，不得进入实现。**
2. **不得跳过 brief 澄清直接出原型**——视距与分辨率未定，字号校准无从谈起。
3. **红线未全过，不得进入评审**；过不了先修复或回原型。
4. **碰红线或改骨架 → 回原型重选。**
5. **未登记的建议值偏离视为缺陷。**

### 3. brief 最小问题清单（7 项）

| # | 问题 | 作用 |
| --- | --- | --- |
| 1 | 业务域 / 场景 | 决定模板选型（T1–T4） |
| 2 | 核心指标（3–9 个） | 决定 KPI 条与区块内容 |
| 3 | 数据源与刷新频率 | 决定四态（尤其"陈旧"） |
| 4 | **目标屏：尺寸、分辨率、视距** | **决定字号校准**（05 的公式） |
| 5 | 主题 | 库主题之一 / 自定义 |
| 6 | 交互要求（有/无、点击/下钻） | 决定静态展示还是可交互 |
| 7 | 交付形态（静态 HTML / Vue / React / 其他） | 决定实现方式与图表接入 |

### 4. 自检与评审

- **自检清单从 04 的条目 1:1 派生**（红线二值 / 建议值三档），**不另写一套**。
- **跑两次**：实现完成后一次；每次改动后重跑。
- **必须能查出硬编码值**——检查是否用了 `--dvk-screen-*` 令牌而非写死 px。
- **评审由项目负责人本人做**，依据 = 自检报告 + 实际打开大屏。
- **评审发现逐条转成 skill 修订项**，写在 `review.md` 的"skill 修订项"节；**否则评审不算完成**。
