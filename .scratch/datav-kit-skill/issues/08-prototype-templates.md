# 原型模板清单与内容规格

Status: resolved
Type: grilling
Blocked by: 04, 05, 07, 14

## Question

定 3–5 套原型骨架模板的确切清单与每套的内容规格：

1. 出哪几套版式？（候选：三栏运维 / 两栏+主视图 / 单栏叙事 / KPI 顶栏+分栏）顶栏形态由 14 裁决。
2. 每套的：栅格结构（**07 已定 12 列 / 沟槽 24 / 外边距 48 / 8pt 刻度**，留白用**氛围层填充**）、区块清单、使用的组件（tag + 关键属性）、占位数据的形状、主题切换方式。
3. 哪些部分 agent 可改写、哪些是骨架红线——**按 06 的三档模型判定**（硬红线 / 建议值 / 自由区），并注意骨架改动一律回原型。
4. 技术形态：单文件 HTML + import map？**必须引 `assets/tokens.css`（05 产出）**，并把可覆盖的令牌暴露成项目层变量。CDN 选 esm.sh 还是 jsDelivr `+esm`？主题 CSS 怎么引？
5. 模板里图表占位怎么表达（与 10 对齐）。

**产出**：每套模板的规格说明（可直接实现）。


## Answer

### 1. 四套模板

顶栏 / KPI 条为共享结构，差异集中在主区。

| # | 版式 | 骨架行 | 主区 12 列分配 | 主区区块（pattern 引用） | 适用 |
| --- | --- | --- | --- | --- | --- |
| **T1** | 三栏运维 | 顶栏 104 / KPI 104 / 主区 1fr | 3 / 6 / 3 | 左：P6+P7+P9 或 P10 ×2；中：P6+P17 主视图 + P12 底部条；右：P11 / P15 / P13 ×2–3 | 监控、指挥、值班 |
| **T2** | 两栏分析 | 顶栏 104 / KPI 104 / 主区 1fr | 8 / 4 | 主区：P6 + 图表槽 ×2（上下）；侧栏：P10 + P15 | 趋势、对比、归因 |
| **T3** | 单栏叙事 | 顶栏 104 / 主区 1fr / 底部节奏条 104 | 满宽 | P6+P17 主视图 + 3 个并排小面板（P9/P14/P16） | 态势总览、汇报 |
| **T4** | KPI 主导 | 顶栏 104 / KPI 208 / 主区 1fr | 6 / 6 | 上：P4 放大 KPI 卡 ×6（P14/P16）；下：P6+P7 面板 ×2（P9/P10） | 指标看板、经营驾驶舱 |

### 2. 每套模板的规格四段

1. **骨架** —— 行定义 + 12 列跨度 + 流式行高（`minmax(0,1fr)`）。
2. **区块清单** —— 每个区块引用 pattern 编号 + 用途一句话。
3. **组件构成** —— tag + 关键属性（`colors`、`glow-intensity`、`fit-screen` 参数）。
4. **占位数据形状** —— 每个区块的假数据字段与条数（内联 JSON）。

### 3. 三档权限

| 档位 | 内容 |
| --- | --- |
| **骨架红线**（改则回原型） | 行数、列数、主视图位置、顶栏形态、区块增删 |
| **建议值**（可改需登记） | 区块比例（列宽）、间距、密度、装饰强度、主题 |
| **自由区** | 区块内的 pattern 替换（P9↔P10↔P11）、业务文案、图表类型与 option、占位数据 |

### 4. 技术形态

- **每套一个纯 HTML 单文件**（原生 JS，不用 Vue），满足"双击打开就能看"。
- **import map** 把 `@datav-kit/elements@0.0.5` 映射到 CDN；**jsDelivr `+esm` 为主、esm.sh 为备**（均实测可用）。
- **引 `assets/tokens.css`**（05 产出），可覆盖的令牌暴露成项目层变量。
- **主题切换**：根容器挂 `.dvk-theme-<name>` 类，在 5 套库主题间切换；项目自定义主题同机制接入。
- **顶栏**：按 14 的裁决做特性检测二选一（`customElements.get('dvk-title-1')`）。
- **图表槽位填一个最小 ECharts 实例**（引用「图表指导与 ECharts 参考实现」的产出——ECharts 是原型的参考实现，不代表项目实现必须用它），不放空槽——空槽会让原型失真，违背"原型即视觉契约"。
