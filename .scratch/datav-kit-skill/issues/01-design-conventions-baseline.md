# 大屏设计规范的行业事实基线

Status: resolved
Type: research

## Question

为"新建一套 datav-kit 大屏设计规范"取事实基线（注意：现有两套 Demo 不作为基准，只作参考）。需要回答：

1. 通用大屏 / 数据可视化设计规范包含哪些维度？（画布与栅格、间距刻度、字阶与层级、颜色角色、信息密度、动效预算、装饰预算、留白、对比度、可访问性）
2. 哪些条目有**可验证的量化阈值**？（如对比度 4.5:1 / 3:1、最小字号、动效时长上限、每屏主色数量上限、单屏装饰元素上限）——给出出处。
3. OpenAI `data-visualization` 质量门的具体条目原文，尤其"颜色角色账本""标注优先于图例""反 AI 味清单"三段。
4. 大屏特有约束：1920×1080 / 超宽 21:9 / 拼接屏的安全边距、观看距离与字号关系、等比缩放对线宽与字号的影响、暗色场景下的对比度。
5. 常见反模式清单（碎片化拼贴、装饰抢焦点、按钮化/图标化装饰、动效疲劳、图例漂移、无意义的渐变与光晕）。

**产出**：`.scratch/datav-kit-skill/assets/r1-design-conventions.md`（中文，每条结论附出处链接）。
**注意**：只做事实收集与出处核对，不做取舍决策——取舍在 04。

## Answer

事实基线与逐条出处已写入 **`.scratch/datav-kit-skill/assets/r1-design-conventions.md`**（中文，约 500 行，每条结论带链接与可信度分级：规范 / 官方指南 / 学术 / 实践观点 / 本仓库事实 / 本文件计算）。要点：

- **规范覆盖 10 个维度**：画布与栅格、间距刻度、字阶与层级、颜色角色、信息密度、动效预算、**装饰预算**、留白、对比度、可访问性。前 9 个在 Material / Carbon / Ant Design 里都有对应章节；**第 7 个"装饰预算"是主流设计系统的空白**，没有现成标准可引。
- **对比度（WCAG 2.2，规范性）**：正文 ≥ 4.5:1，大字 ≥ 3:1（大字 = ≥18pt / 14pt 粗体 / CJK 等效，pt→px 为 1pt=1.333px，即 ≈24px / 18.5px）；AAA 为 7:1 / 4.5:1；非文字（UI 组件、理解内容所必需的图形）≥ 3:1。**对比度不可四舍五入（4.499:1 ≠ 4.5:1）**。**另有可引用的上限**：FAA/NATS"对比度超过 **15:1** 可能引起视觉不适"、MIL-STD-1472H 字符对比 **6:1–10:1 最佳**、APCA（WCAG 3 候选）"Dark Mode Maximum Lc −90"防 halation。**WCAG 本身不设上限**，所以上限只能引工程标准/草案。
- **动效（WCAG 2.2，规范性）**：自动播放的动效持续 **>5 秒**必须可暂停/停止/隐藏；自动更新信息必须可暂停或可控制频率（无 5 秒豁免）；闪烁 ≤ 每秒 3 次；交互动效必须可关闭（2.3.3，AAA）。
- **动效时长的官方数值**：NN/g 100–500ms（简单反馈 ~100ms，模态 200–300ms，400ms 是慢上限）；Carbon token 70/110/150/240/400/700ms，微交互自检 90–120ms；Ant Design 0.1/0.2/0.3s；Material M3 50–1000ms 分档。**对照本仓库 `--dvk-motion-duration` 为 2200–2600ms（秒级装饰动画）——量级差一个数量级。**
- **"每屏主色数量上限"没有标准。** 只有官方建议：Datawrapper "≤7"、ColorBrewer 分类色板 ≤12、Carbon 14 色、ECharts 默认 9 色、AntD 12 主色、OpenAI "一主一辅强调色"。**"单屏装饰元素上限"连官方建议都没有。** 这两项若要写进规范，只能自定阈值并标注为自定义。
- **尺寸阈值**：指针目标 ≥24×24 CSS px（AA）/ 44×44（AAA），移动主控推荐 44–48px；文字可放大至 200%；文本间距 1.5×/2×/0.12em/0.16em；行长 ≤80 字符（CJK 40）；重排基准 320 CSS px；焦点外观 ≥2 CSS px 周长且 ≥3:1。
- **OpenAI 质量门原文已完整摘录**（commit `1e28582`，2026-05-28）：颜色角色账本（SKILL.md 4 项 + 基础文档 10 项角色、6 条判据）、"直接标注优先于分离图例"、反"通用 AI 氛围"清单（broad brush strokes / wispy ribbons / bokeh·orbs / one-hue drama / cinematic wallpaper / decorative gradients）。核心判据：**"每个 glow/pulse/halo/blur/particle/shimmer/animation 都必须有一个具名的数据或交互映射；只'好看'就删掉。"**
- **大屏安全边距（三套标准，原文已核实）**：SMPTE ST 2046-1:2009 规定 1920×1080 的 Safe Action = 宽高 **93%**（1786×1004，左右各 ~67px、上下各 ~38px）、Safe Title = **90%**（1728×972，左右各 ~96px、上下各 ~54px）；EBU R95 v1.1 与 ITU-R BT.1848 则是 **action safe 内缩 3.5% / graphics safe 内缩 5%**。ITU 明言"**数字电视的过扫描既无必要也不可取**"——所以三套都只是保守参照，不是大屏硬规则。
- **中文团体标准（本次最重要的额外发现）**：**T/CIDADS 00011-2022《数字大屏可视化设计指南》**（中国工业设计协会，2022-06-14 发布 / 09-08 实施，15 页，阿里云等起草）——视距宜 **≥150cm**；垂直视域 **20°–28°**、水平 **36°–48°**；最佳视距 `S1=2.005h` ～ `S2=2.835h`；**最小字号物理高度 = 视距/200**（公式 `(S/200)×(R/H)`；3840×2160、屏高 2.25m、视距 5m → **24px**）；**同屏字体 ≤2 种**；**白色面积 ≤40%**；**动效 200–600ms**；文字对比度符合 WCAG AA；**拼接屏拼缝 0.5–3.5mm**、高度 1080px（3×5 = 1080×3200px）。**注意：条款经第三方文档站转述取得，官方原文未获得**，引用时须标注来源等级。
- **观看距离与字号（多标准交叉核实）**：ISO 9241-303:2008 §5.5.4 与 ANSI/HFES 100 §4.9.1 均为字符张角 **≥16 弧分、20–22 弧分推荐**；**ISO 9241-3:1992 §6.4 额外规定彩色字符 ≥21 弧分、30 弧分推荐**——大屏默认就是彩色字符，直接影响最小字号取值。换算：16 弧分 = 3m→14.0mm、5m→23.3mm、10m→46.5mm；在 55″ 的 1920×1080 上为 **3m→22px、5m→37px、10m→73px**。**交叉验证**：T/CIDADS 的 `1/200` = **17.2 弧分**，落在 16 与 20–22 之间；ISO 11064-4 的速算规则"**最大视距 = 215 × 字符高度**"与 16 弧分完全等价。
- **等比缩放（CSS Transforms 规范）**：`transform: scale()` 是**布局之后**的视觉变换，不影响布局流。因此 `--dvk-line-width: 1px` 在 `contain` 且视口小于 1920×1080 时会被缩成**亚像素**；`fill` 模式则非等比拉伸字形与线宽。标准解法是 SVG 的 `vector-effect: non-scaling-stroke`。
- **暗色场景（Material 官方原文）**：暗色表面推荐 **#121212**（不是纯黑），要求"表面 + 100% 白正文 ≥ **15.8:1**"，以保证最高 elevation（24dp）表面上正文仍 ≥4.5:1；白色 elevation 叠加 0%→16%；浅色文字不透明度 87%/60%/38%；**"不要用光晕代替阴影表达层级"**；强调色需降饱和。Carbon 用 #161616/#262626 且"避免中间调"；AntD 明确"暗黑模式下避免使用对比很强的色彩或内容"。**注意：Material 的 15.8:1 经复算不能复现**（#FFF 在 #121212 上 = 18.73:1，在 #232323 上 = 15.72:1），引用时不要写成"#121212 上必须 15.8:1"。另：Piepenbrock 2014 证明**字号越小，亮字暗底越吃亏**；控制室大屏标称亮度 **250 cd/m² 足够、>500 cd/m² 可能过亮**（Christie）。
- **反模式**已有量化判据：3D 饼/柱（ECharts、Wilke）、双轴（Datawrapper）、彩虹色阶（Moreland）、截断 y 轴（柱状必须从 0，折线不必）、过度绘制与过度平滑（Wilke）、图例高度 ≤ 图表高度 30%（Carbon）、折线 ≤4 条 / 仪表指针 ≤3 个 / 饼图分类 ≤5（ECharts Handbook）。
- **中文来源分级**：Ant Design 官方规范可作 [官方指南] 引用（"总模块数量 5-9 个"、"Data-ink Ratio"、"不过度修饰"）；网易、京东云的文章是 [实践观点]；**AntV 官方规范、华为设计指南、腾讯 CDC、百度 EUX 本次均无法取回原文**（JS 渲染或 502）。
- **未能验证清单**（详见 asset §6）：21:9 无任何标准；**"安全边距"没有任何标准给出 px 值**（T/CIDADS 未给，SMPTE/EBU/ITU 只给百分比）；**"页头 60–100px""内边距 24/32/40px"这类常见说法找不到任何可信出处**；LED"点间距×N"规则各厂商相差 2 倍以上（Christie 8ft/mm vs Absen 1mm=1m）；暗色 halation 无规范定量表述；ISO 9241-303 与 ISO 11064 原文付费未取得（ISO 11064-6 仅取到俄文采标文本的照明条款）；T/CIDADS 00011-2022 官方原文未取得（条款经第三方文档站转述）；Material/AntD/AntV 站点均为 JS 渲染，已改用官方 token 文件与仓库 markdown 源。

**注意**：本 ticket 只做事实收集，不做取舍；画布尺寸、栅格列数、字号梯度、装饰预算的具体取值由 04 / 05 / 07 决定。
